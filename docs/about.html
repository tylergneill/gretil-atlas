About

GRETIL, the Göttingen Register of Electronic Texts in Indian Languages, is a collection of machine-readable Indic texts contributed by many hands and published by the Göttingen State and University Library from 2001 to 2020. It was declared closed in July 2025 and archived to TextGrid.

This unofficial “atlas” interface — not affiliated in any way — offers a better way to explore the contents of its Sanskrit section. It is an "atlas" in the sense that it not only charts the navigable waters — with more transparent browsing by category and author — but also plumbs their depths — with visibility into sizes, counts, and changes over time that the source collection doesn't surface on its own. It is not a mirror, as it hosts no text of its own; instead, every entry links to the files in a separate mirror of the site, scraped in November 2025.

For more perspective on this and sibling Atlas projects, see Sāgarasaṅgama.

Practical Intro to GRETIL Structure

Two Overlapping Layers: Legacy HTML and TEI

GRETIL kept its Sanskrit texts in two layers. The older one is a tree of legacy HTML files, sorted into category folders. The newer one is a flat set of TEI XML files, nearly all converted from the legacy files between 2017 and 2020, each published with an HTML and a plaintext transformation beside it.

Neither layer contains the other. The महाभारत and the शतपथब्राह्मण, among others, were never converted, and texts were born in TEI and have no legacy file at all. Counted as texts rather than files, the two layers overlap like this:

Filenames, Files and Texts

The two layers name their files very differently. Legacy filenames are eight cryptic characters; TEI filenames spell out author and title in Harvard-Kyoto. The same ऐतरेयोपनिषद् with commentary is aitupsbu.htm in one layer and sa_aitareyopaniSad-comm.xml in the other.

The legacy files hold far fewer texts, for two reasons. A long text is often split into parts, one file per book or chapter: the महाभारत is eighteen files, one per parvan. And beside a text's own file there are often secondary files: other layouts of the same text — with pada markers (…au.htm), plain (…pu.htm), in pausa (…xu.htm), accented, or an earlier revision — and word indexes to it (…iu.htm). Of the legacy files, are texts or parts of texts and are secondary: other layouts and indexes. A layout is counted as the text only when no regular version of it exists.

The letter before the final u hints at the layout but is not a reliable code, and files with the same stem are not always the same text: ram_03_u.htm is John Smith's revision of the अरण्यकाण्ड, while ram_03au.htm and ram_03pu.htm are Oliver Hellwig's, with and without pada markers. The Atlas therefore assigns each legacy file to its text by comparing the texts themselves and reading the file headers (see What Counts as a Text).

Categories

The legacy tree is the only categorisation GRETIL has. Its top-level folders — Veda, Epics, Purāṇa, Religious literature, Poetry, Śāstra, and a small one for texts from Indonesia — divide into finer ones, some two levels down (Śāstra › Philosophy › Mīmāṃsā). Every legacy file sits in exactly one folder. The TEI layer is flat and carries no category of its own.

Metadata

A legacy file has a <title>, typically Author: Title without diacritics, and a free prose header naming the edition and the people who input the text. There are no dates and no structured fields.

A TEI file has a proper header: title and author with diacritics, the roles of those who input and converted it, the source edition, and the legacy header carried over verbatim. Its one date is the date of TEI publication — of the say 2020 and the other say 2019 — which says nothing about when the text joined the collection.

The Main Page and the Update History

Two pages tie the layers together. The main page is one long outline by category with an entry per text, linking whichever of its files exist. The history page lists numbered, dated updates from November 2001 to September 2020, each naming the texts it added, revised or converted by linking their entries on the main page.

Three Official Versions

GRETIL exists in three official forms that disagree in detail: the downloadable zip of all Sanskrit texts, the file structure of the live site, and the TextGrid archive. The zip is the copy most users have and the least current: it still carries thirteen misfilings which the live site later corrected. The TextGrid archive holds some sixty TEI files more than the live site did.

Sanskrit vs. Other Languages

GRETIL also has sections for Pali, Prakrit, New Indo-Aryan and Dravidian languages. This Atlas covers the Sanskrit section only.

Obtaining and Representing GRETIL Data

No Scraping

Unlike its sibling Atlases, this one fetches nothing. The collection is closed, and the Atlas is built offline, in seconds, from copies already on disk: a scrape of the live site from November 2025 as the primary source, with the downloadable zip and an independent mirror as cross-checks. Where the versions disagree about where a text is filed, the live site's placement is used. The TextGrid archive's additional TEI files are not included yet.

What Counts as a Text

The Atlas counts texts. Files from one digitization — the same input of the same edition — are one text, however they are split, laid out or revised. A different digitization or a different edition is a different text, as is a root text extracted on its own from a commented edition. Grouping texts into works is left to other tools.

Counted that way, GRETIL's Sanskrit section holds texts:

  • converted from legacy HTML to TEI. Each is one TEI file and the legacy files of the same text.
  • born in TEI, with no legacy file.
  • legacy only, never converted. of them come in several parts, among them the महाभारत, the शतपथब्राह्मण and a second digitization of the ऋग्वेद. The main page links only ; the other can be found only by browsing the folders.

A legacy file finds its text in one of three ways. It is the file a TEI header names as its source; or its text is found inside a TEI file, which catches the later parts of texts whose TEI names only the first; or, where layout defeats a comparison of the words (line numbers on every pāda, pausa forms, dissolved sandhi), it has been checked by hand, word for word and against the file headers. Which TEI files were born in TEI is read from their own credits: a TEI file made from a legacy one credits someone with its "conversion to legacy GRETIL formats."

Calculating Size

GRETIL's Sanskrit is IAST throughout, so no transliteration is needed. Size is simply the body of each text: for a legacy file, everything after the header, banner and character table; for a TEI file, everything after the header block of its plaintext transformation. A text in TEI is measured from that transformation; a legacy-only text from its own files, its parts added up, leaving out the other layouts and the indexes.

Calculating Dates

GRETIL published its own record of what it added and when, so dates here are measured rather than inferred. Each update on the history page links the main-page entries of the texts it announces, and each entry links its files; following those links dates a text by the first update that added it. Mentions marked only "revised" or "converted" are not counted as additions.

Browsing by Categories and Authors

The default view is GRETIL's own category tree. A text in TEI takes the category of its legacy files; the texts born in TEI, which have none, are gathered under "TEI without a legacy source." Within a category, texts can optionally also be grouped by author.

Alternatively, the tree can be inverted so that authors are primary and categories secondary. No normalization is performed on author names, so a name spelled with diacritics in a TEI header and without them in a legacy title appears twice (see Data Quality below).

Each text carries a tag link for every file it has: "xml" and "txt" for a TEI file and its plaintext transformation, "htm" for each legacy file of the text itself (one per part), "version" for another layout of it, and "index" for an index to it. A "TEI" or "legacy only" tag says which layer the text was counted from.
